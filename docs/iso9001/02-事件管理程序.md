# 事件管理程序

> 文件编号：ISO-IT-PR-002 | 版本：1.0 | 生效日期：2026-03-26
> 对应条款：ISO 9001:2015 §8.1, §9.1, §10.2

---

## 1. 目的

规范 IT 事件（Incident）的报告、分类、处理及关闭流程，确保服务中断得到及时、有效的响应与恢复。

## 2. 适用范围

适用于所有影响 IT 服务可用性、性能或功能的非计划中断事件。

## 3. 定义

| 术语 | 定义 |
|------|------|
| 事件（Incident） | 导致或可能导致 IT 服务中断或降级的非计划事件 |
| 重大事件（Major Incident） | 影响范围广（>10 人）或核心业务中断超过 30 分钟 |
| 升级（Escalation） | 将事件移交更高级别团队或管理层处理 |

## 4. 事件优先级分级

| 优先级 | 描述 | 响应时间 | 解决时间目标 |
|--------|------|----------|-------------|
| P1 - 紧急 | 核心业务系统全面中断 | 15 分钟内 | 4 小时内 |
| P2 - 高 | 重要功能受损，影响多人 | 30 分钟内 | 8 小时内 |
| P3 - 中 | 单用户功能受损，有临时解决方案 | 2 小时内 | 3 个工作日内 |
| P4 - 低 | 轻微影响，用户可正常工作 | 4 小时内 | 5 个工作日内 |

## 5. 处理流程

```
用户报告事件
    │
    ▼
服务台接单 → 记录工单（含时间戳、描述、联系人）
    │
    ▼
事件分类与优先级评定
    │
    ├─ P1/P2 → 立即升级通知相关主管 + 启动重大事件处理
    │
    ▼
初步诊断与处理
    │
    ├─ 一线无法解决 → 升级至二线/三线支持
    │
    ▼
问题解决 → 与用户确认服务恢复
    │
    ▼
工单关闭 → 更新知识库（如为新类型问题）
    │
    ▼
（P1/P2）事件后检讨（PIR）→ 根本原因分析
```

## 6. 重大事件处理（P1）

1. **15 分钟内** 指定事件负责人（Incident Manager）
2. **每 30 分钟** 向管理层发送状态更新
3. 建立临时沟通频道（如微信群/Teams）
4. 事件解决后 **5 个工作日内** 完成 PIR 报告

## 7. 记录要求

每张工单必须记录以下信息：

- [ ] 工单编号、开单时间
- [ ] 报告人姓名及联系方式
- [ ] 事件描述（现象、影响范围）
- [ ] 优先级评定
- [ ] 处理过程（时间线）
- [ ] 解决方案
- [ ] 关单时间
- [ ] 用户确认签名/回复

## 8. KPI 监控

| 指标 | 目标 |
|------|------|
| P1 响应率（≤15min）| ≥ 95% |
| 首次解决率（FCR）| ≥ 70% |
| 用户满意度（CSAT）| ≥ 4.0/5.0 |
| 工单按时解决率 | ≥ 90% |
